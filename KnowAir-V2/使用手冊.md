# KnowAir-V2 使用手冊

本手冊涵蓋根目錄的資料前處理、模型訓練與評估。ERA5/CNEMC 時間延伸資料及 DCRNN 微調請另讀 [`finetune/使用手冊.md`](finetune/使用手冊.md) 和 [`finetune/Readme.md`](finetune/Readme.md)。

## 1. 環境準備

從 repository 根目錄建立 Python 虛擬環境並安裝專案依賴：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

請確認 PyTorch 可使用預期的 CPU/GPU。讀取 netCDF 需要 `xarray` 和 netCDF backend；AirPhyNet 需要 `torchdiffeq`。套件以 repository 根目錄的 `requirements.txt` 為準。

## 2. 取得原始資料

從 [KnowAir-V2 Zenodo 頁面](https://doi.org/10.5281/zenodo.15614907) 下載資料檔，依資料集實際提供內容放入 `KnowAir-V2/data/`。前處理預期檔名為 `dataset_yrd.nc`、`dataset_bthsa.nc`，並使用版控中的 `stations_yrd.csv`、`stations_bthsa.csv`。大型原始檔通常不納入 Git。

執行前可檢查 `data/` 內容：

```text
KnowAir-V2/data/
├── dataset_yrd.nc
├── dataset_bthsa.nc
├── stations_yrd.csv
└── stations_bthsa.csv
```

若下載檔案名稱或欄位不同，先對照 `preprocess_knowair.py` 中的變數候選名稱與實際 netCDF 內容。

## 3. 前處理

由 repository 根目錄執行：

```bash
cd KnowAir-V2
python preprocess_knowair.py --region yrd --raw_dir data
python preprocess_knowair.py --region bthsa --raw_dir data
```

輸出分別寫入 `data/processed_yrd/` 和 `data/processed_bthsa/`。常用產物如下：

| 檔案 | 用途 |
|---|---|
| `features.npy` | 標準化後時序特徵，形狀為 `[時間, 站點, 特徵]` |
| `features_raw.npy` | 未標準化特徵（若該流程有產生） |
| `adj_mx.npy`、`adj_wind.npy` | 地理圖及風場相關圖矩陣 |
| `dist_mx.npy` | 站點間距離矩陣 |
| `stations.csv`、`timestamps.csv` | 節點索引與時間索引 |
| `scalers.pkl` | 特徵標準化參數 |
| `split.pkl` | train/validation/test 時段切分 |

第一次處理新版本資料時，檢查程式列出的 netCDF 變數、站點數、特徵順序、時間範圍與缺值情況。若站點欄位或變數無法辨識，先修正輸入 metadata 或 `preprocess_knowair.py` 的對照設定，再開始訓練。

## 4. 訓練模型

以下命令假設目前工作目錄是 `KnowAir-V2/`。`--data` 指向前處理輸出目錄；訓練腳本的預設路徑可能是其他資料集，因此建議明確提供該參數。

```bash
python train_dcrnn.py     --data data/processed_yrd
python train_agcrn.py     --data data/processed_yrd
python train_gts.py       --data data/processed_yrd
python train_airphynet.py --data data/processed_yrd
```

將 `processed_yrd` 換成 `processed_bthsa` 可訓練另一區域。各腳本支援的超參數以 `python train_dcrnn.py --help` 等命令顯示為準；常見選項包括歷史長度、預測長度、batch size、epoch、learning rate、patience 和 checkpoint 目錄。

DCRNN 的 demo 腳本另支援 TensorBoard，以及程式設定的可選 W&B 記錄：

```bash
python train_dcrnn_demo.py --data data/processed_yrd --exp_name yrd_demo
```

訓練結束後記下輸出的 checkpoint 路徑、資料目錄、超參數與訓練切分。不要將不同資料集或站點排列的權重與資料混用。

## 5. 評估 checkpoint

通用評估腳本支援四種模型。依實際 checkpoint 指定檔案：

```bash
python test_models.py --model dcrnn --ckpt checkpoints_yrd/dcrnn_faithful_best.pt \
  --data data/processed_yrd --splits val test --per_horizon
```

`--model` 可用 `dcrnn`、`agcrn`、`gts` 或 `airphynet`。checkpoint 若保存訓練參數，腳本會用其中參數重建模型；`--data` 可明確覆寫 checkpoint 記錄的資料路徑。`test_gts.py` 是 GTS 的獨立評估入口，使用前以 `--help` 確認目前參數。

`test_extended_horizon.py` 可用訓練於較短預測窗的 DCRNN checkpoint 延長自迴歸推論步數，例如：

```bash
python test_extended_horizon.py --ckpt checkpoints/dcrnn_faithful_yrd_24h_best.pt
```

延長推論只增加解碼步數，不會讓模型因此學會長時距預測；結果通常會隨預測步數增加而退化，應視為外推評估。

## 6. 訓練紀錄與結果

DCRNN demo 與 fine-tune 會寫 TensorBoard event；其他訓練腳本未必輸出相同格式的 log。於 `KnowAir-V2/` 開啟 demo 記錄：

```bash
tensorboard --logdir runs --port 6006
```

微調記錄則在 `finetune/` 目錄執行：

```bash
tensorboard --logdir runs_finetune --port 6006
```

瀏覽器開啟 `http://localhost:6006`。Checkpoint 通常保存模型權重、訓練參數及驗證指標；fine-tune 的 JSON 報告和指標解讀見 [`finetune/Introduction.md`](finetune/Introduction.md)。

## 常見問題

- **找不到 netCDF 變數**：列印/檢查檔案中的實際變數名稱，對照 `preprocess_knowair.py` 的 `VAR_MAP_CANDIDATES`。
- **找不到資料檔或目錄**：確認命令的工作目錄，並將 `--raw_dir`、`--data` 設成相對於目前工作目錄的正確路徑。
- **checkpoint 維度不符**：確認資料區域、節點數、站點順序和模型設定與訓練 checkpoint 完全一致。
- **AirPhyNet 無法匯入**：安裝 requirements 中的 `torchdiffeq`，並確認目前啟用的是預期虛擬環境。
- **GPU 記憶體不足**：降低 `--batch_size`；調整後的訓練設定需記錄，以便與其他實驗正確比較。
